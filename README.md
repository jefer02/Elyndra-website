# Elyndra website

The showcase and download site for **[Elyndra](https://github.com/jefer02/Elyndra)**, the
console-style game launcher for Android. Static output, deployed on Cloudflare (Workers static
assets). English and Spanish.

> **The site never hosts the APK.** Every download button points at the asset on
> [GitHub Releases](https://github.com/jefer02/Elyndra/releases). The site only reads the public
> release list to show the version, date, size and SHA-256.

## Stack

**Vite 8 + TypeScript, no UI framework.** Every page is rendered to static HTML at build time from
typed templates and dictionaries, so the content, the download link and SEO work without
JavaScript, and the browser only gets ~11 KB (gzip) of JS for the interactive layer. **three.js**
is used for one thing only, Masha's 3D hologram, and is lazy-loaded when that section approaches
(~160 KB gzip, never on the first load). No GSAP or smooth-scroll library: the wheel, the reveal
and the parallax are a few hundred lines of plain TypeScript and CSS.

Exact versions are pinned in `package.json` (and `.npmrc` sets `save-exact`). Node 24 (`.nvmrc`).

## Run it

```bash
npm ci              # install (about 20 s)
npm run dev         # http://localhost:5173 (pages re-render when src/pages or src/i18n change)
npm run build       # snapshot of releases → typecheck → vite build → size budget, into dist/
npm run preview     # serve dist/ at http://localhost:4173
npm run cf:dev      # serve dist/ with Cloudflare's own runtime (headers, 404, redirects)
```

`SITE_URL` sets the public origin used for canonical links, `og:url`, absolute `og:image`,
`sitemap.xml` and `robots.txt`. Set it in production builds (for example in the Cloudflare build
variables):

```bash
SITE_URL=https://elyndra.example npm run build
```

Without it the build still works and warns: no sitemap, no canonical, relative `og:image`.

Deploying: see **[CLOUDFLARE_DEPLOY.md](CLOUDFLARE_DEPLOY.md)** (in Spanish).

## How downloads work

1. On load, the browser asks the public GitHub API for `jefer02/Elyndra` releases (no token).
2. It takes the **newest published release, pre-releases included** (a *Beta* badge marks them;
   drafts are never used).
3. It picks the APK the same way the in-app updater does (`docs/RELEASING.md` in the app repo):
   the device's ABI when the browser can tell it (`arm64-v8a`, `armeabi-v7a`, `x86_64`, `x86`),
   otherwise `universal`. Other APKs of the release are listed with size and checksum.
4. It shows the version, date, size and the **SHA-256 from the asset's `digest`**, with a copy
   button and the commands to check it.
5. On Android the main button downloads directly. On desktop it shows a QR code (generated in the
   browser) that opens the page on the phone, plus the direct link.

Fallbacks, in order:

| Situation | What the visitor gets |
|---|---|
| Response cached in this tab (15 min, `sessionStorage`) | Instant, no request |
| GitHub API answers | Live data |
| API rate-limited (60 requests/hour per IP), blocked or offline | `/data/releases.json`, the snapshot written at build time, with a note saying so |
| Snapshot also unavailable | A message and the link to the Releases page |
| JavaScript off | The page was prerendered with the snapshot's version and size; buttons link to the Releases page |

New app releases appear on the site **without rebuilding it**, because step 1 happens in the
browser. Rebuilding only refreshes the fallback snapshot.

## Project layout

```
index.html, es/index.html,         page stubs; the real HTML is rendered by vite.config.ts
privacy/…, es/privacy/…, 404.html
src/pages/        build-time templates (layout, home, privacy + 404, icons)
src/i18n/         en.ts (default, source of truth), es.ts, locale registry
src/data.ts       repo URLs, systems list, palettes, release parsing and APK choice (shared)
src/modules/      browser code: download, meridian wheel, boot sequence, aurora shader,
                  Masha 3D (lazy), gamepad, sound, palette, gallery, nav, reveal, tilt
src/styles/       tokens.css (the app's tokens), base.css, sections.css
public/           fonts (WOFF2 subsets + OFL), img, models/masha-web.glb, og.jpg,
                  data/releases.json (snapshot), licenses, _redirects, site.webmanifest
public/video/     device recordings encoded by `npm run video` (WebM + MP4 + first frame), in git
assets-src/       originals, NOT in git (see Assets): screenshots/ and brand/ for `npm run assets`,
                  video/ (raw adb recordings) for `npm run video`
scripts/          snapshot-releases, optimize-assets, build-masha, render-og (+ og.html), postbuild
wrangler.jsonc    Cloudflare Workers static assets config
```

`dist/_headers` (security headers, CSP with the hash of the one inline script, caching),
`robots.txt` and `sitemap.xml` are generated by the build.

## Content rules

Every claim on the site is checked against the app's code and docs. When the app changes, update
`src/i18n/en.ts` first, then the other languages. Systems come from the app's `data/Systems.kt`;
palettes from `data/SignaturePalette.kt`; colors and radii from `data/BrandTokens.kt` and
`ui/theme/Console.kt`.

### Adding a language (pt, fr, de, ja)

1. Copy `src/i18n/es.ts` to `src/i18n/xx.ts` and translate it (TypeScript flags any missing key).
2. Add it to `LOCALES` in `src/i18n/index.ts`.
3. Create the stubs `xx/index.html` and `xx/privacy/index.html` (copy the `es/` ones).
4. Japanese also needs a font with Japanese glyphs: the self-hosted Poppins subset is Latin only.

## Assets

> **`assets-src/` is not in git, and neither is `assets-src/video/`** (`.gitignore` excludes the
> whole folder). They hold the originals: device screenshots, brand files and the raw recordings
> (~27 MB). Only the web versions they produce (`public/img/`, `public/video/`) are committed, so
> the build and Cloudflare never need them. **Copy `assets-src/` by hand** when you move or clone
> the project, and **keep a backup** of it (an external drive or a cloud folder): without it the
> screenshots and videos cannot be re-encoded.

| Command | What it does |
|---|---|
| `npm run assets` | `assets-src/` → `public/img/` (AVIF + WebP at two widths, icons), with a per-file size cap |
| `npm run masha -- <path to masha_lite.glb>` | Builds `public/models/masha-web.glb` from the app's model: CC0 geometry and skeleton only, **no animation clips**, meshopt-compressed (≈620 KB) |
| `npm run snapshot` | Refreshes `public/data/releases.json` (also part of `build`) |
| `npm run video` | Encodes the device recordings in `assets-src/video/*.mp4` (not in git) into short silent loops in `public/video/`: VP9 WebM + H.264 MP4 + a JPEG first frame, no audio, ≤ 2.6 MB each (today 0.2–1 MB). Crops the ZUI caption bar (top 70 px) and side-panel handle (right 24 px). Needs ffmpeg on `PATH` (`winget install Gyan.FFmpeg`) or `FFMPEG=C:\path\to\ffmpeg.exe`. When the files exist, the build uses `wheel` for the Meridian feature art and `masha` for Masha's stage (only fetched when 3D is unavailable). `assets-src/video/intro.mp4` is kept but not encoded or published. Run it again, then rebuild, after changing a recording or the trim points in the script |
| `node scripts/render-og.mjs` | Re-renders `public/og.jpg` from `scripts/og.html` (needs Playwright, see the script) |

Screenshots lose a 14 px strip on the left, where the tablet's system edge handle appears. Device captures
(Lenovo Legion Y700, `adb exec-out screencap`) also lose the top 70 px ZUI caption bar before they go
into `assets-src/screenshots/` at 1600 px wide. Never capture Settings → APIs.

## Motion, accessibility and low-power behavior

- `prefers-reduced-motion`: no boot sequence, no drifting, the wheel snaps, Masha is a still frame.
- Low power (Save-Data, ≤ 2 GB RAM or ≤ 2 cores): Masha waits for a button instead of autoloading.
- Device recordings play only while visible (paused when scrolled away, when the wheel shows another
  card, or once Masha's 3D model takes the stage), never with reduced motion or low power. Their
  first frame is a lazy `<img>`, not a `poster`, so nothing video-related competes with the first
  load. Without JS that frame is what shows.
- The WebGL aurora only starts on desktop, after the first interaction, at half resolution, and
  stays off on software renderers; everyone else gets the CSS aurora (compositor-only).
- Everything works with keyboard, touch and a gamepad (Gamepad API: D-pad moves, LB/RB change
  section, A activates or downloads, B goes back). Focus is always visible.
- Text contrast ≥ 4.5:1 in all five palettes.

## Privacy

No cookies, analytics or third-party requests other than `api.github.com` (release list) and the
downloads from GitHub. Fonts, images and scripts are self-hosted. Wrangler telemetry is off in
`wrangler.jsonc`.
